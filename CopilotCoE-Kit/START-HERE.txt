MICROSOFT 365 COPILOT COE - IMPLEMENTATION KIT
Master kit | Prepared by David Shih Chun Liu
This is a Teams/SharePoint CoE, not the
Power Platform CoE Starter Kit. All seeded content is starter material for the
organization's review; none of it is adopted policy.

ONE KIT, ANY ORGANIZATION
  The kit is the same for every organization. Everything organization-specific
  (tenant, names, support mailbox, policy links, Top 10 deck, policies, videos)
  lives in an ORGANIZATION FOLDER that you pass to every script with -OrgPath.
  Start from Org-Template (higher education) or ContentPacks\Government-StateLocal (state and
  local government, commercial or GCC-Moderate), or from your supplied organization folder.
  The choice also sets the base prompts in the Copilot Prompt Library (higher-ed or government);
  the organization's own prompts go in <OrgPath>\Content\OrgPrompts (see the README there).
  Building for another organization never requires repackaging the ZIP.

QUICK START - RUN THE NUMBERED SCRIPTS IN ORDER (01, 02, then 03 when needed; 04 only to undo)
  1. Right-click the ZIP > Properties > Unblock (if shown), then Extract All.
     Keep the folder structure.
  2. Open PowerShell 7 and run:
       cd <extracted-folder>\03_Build\CopilotCoE-Kit
       Install-Module PnP.PowerShell -RequiredVersion 3.2.0 -Scope CurrentUser
  3. Create the organization folder, outside the kit, for example:
       Copy-Item .\Org-Template C:\CoE-Orgs\Contoso -Recurse
     (or use your supplied organization folder). In its Deployment-Settings.json
     replace every <placeholder>: Tenant, AdminFQDN, SiteFQDN, SharedChannelOwnerUPN,
     OrgName, SupportEmail. OrgNoun is optional; blank means "organization".
     OrgName is the actual organization name; DisplayName is the optional hub/Team title.
     If OrgName is blank, DisplayName supplies the organization name. One shared resolver
     supplies all page tokens for install and update; no previous tenant name is reused.
     Keep TeamVisibility set to Private. Confirm
     OrganizationEmailDomains and GovernanceAdditionalAllowedMembers with your security owner.
     AdminFQDN and SiteFQDN are host names only,
     e.g. contoso-admin.sharepoint.com and contoso.sharepoint.com. Add policy and
     training links if you have them. Configure Links.ServiceDesk, TechnologyRequest,
     AIGuidelines and DataSafetyIncident before launch. The incident route is separate
     from ordinary support. Missing routes are visibly marked, not treated as working
     endpoints. Leave PnPClientID empty; script 01 fills it in.
  4. Optional: list agent seed proposals (name, description, Copilot Chat link) under Agents in
     the settings file, and drop files to host into the folder's Assets subfolders
     (Top10, RAI-Policies, Roadmap, Success-Stories, Training, Service-Catalog, Agents).
     The installer lists them and asks before hosting anything.
     New agent links default to pending approval with legacy status Submitted. Reviewed seed publication and
     catalog reviewer membership are described in Org-Template\README.txt.
  5. An approved consent approver with just-in-time admin access runs (once per tenant):
       .\01_Register-CoEProvisioningApp.ps1 -OrgPath C:\CoE-Orgs\Contoso
     Then confirm in Entra > App registrations > Copilot CoE Provisioning (PnP)
     > API permissions that all five permissions show Granted (including delegated User.Read.All,
     used to verify governance users' Member/Guest account type). User.ReadBasic.All cannot
     read userType. For an existing app, add User.Read.All, grant admin consent, then clear
     sign in again with installer -ForceAuthentication before installation. Another organization
     in the same tenant can reuse the app: copy PnPClientID into its settings file.
     Review the delegated scopes with your security team. The app uses SharePoint
     AllSites.FullControl; delete the app and revoke consent when it is no longer
     needed, and clear the persisted PnP sign-in after the work is complete.
  6. SharePoint + Teams administrator runs (once) from a SHA256-verified, freshly extracted
     release ZIP with a unique alias in the organization settings:
       .\02_Install-CopilotCoE.ps1 -OrgPath C:\CoE-Orgs\Contoso -ContentMode Customer -SeedDemoContent
     The signed-in administrator is shown as the author of the three welcome posts. Use
     an approved CoE-owner/provisioning identity. Review every Assets file before adding
     -AcceptOrgAssets; without it, the script asks before hosting eligible files.
     Do NOT add -ResumeExisting to a fresh build. Every run saves a transcript to
     <organization folder>\RevisionAudit\<run id>-transcript.txt, including runs that fail.
     If a run stops partway, verify the exact Team and site, fix the cause, and
     use -ResumeExisting as described below. A fresh kit acceptance run instead
     needs a new alias or a separately reviewed removal; never purge on an error alone.
  6b. Check the result (read-only), using the exact site URL printed by install:
       .\Test-CoEInstall.ps1 -OrgPath C:\CoE-Orgs\Contoso -SiteUrl https://contoso.sharepoint.com/sites/CopilotCoE -ContentMode Customer
      ALL CHECKS PASSED reports no automated FAIL; a WARN still requires its named
      manual check. A header-layout or long-title/menu-overflow WARN needs a
      1366px site screenshot. When
      ChannelMessage.Read.All is absent, open General, Ask Us Anything and Share Your
      Prompt in Teams; confirm exactly one correct post per channel and no Customer-
      mode sample notice. Do not expand tenant-wide message-reading consent merely
      to silence this warning. Group.ReadWrite.All can post today, but Microsoft
      Graph supports that scope for message sending only for backward compatibility.
      Use the same -ContentMode in install, update and test (Demo only for an
      internal demonstration with its required notice).
      To validate the full repair/update path on a fresh internal test site:
       .\03_Update-CoEContent.ps1 -OrgPath C:\CoE-Orgs\Contoso -Scope All -RepairCapturedPages -ContentMode Customer
       .\Test-CoEInstall.ps1 -OrgPath C:\CoE-Orgs\Contoso -SiteUrl https://contoso.sharepoint.com/sites/CopilotCoE -ContentMode Customer
      RepairCapturedPages can replace customized content; do not run it on an
      established customer site without review. Recheck all three Teams posts.
      Before accepting a fresh install, visually check and capture Home (readable linked card titles),
      one Copilot tool page, Guided learning, and the Agents menu at normal laptop width.
      Interactive browser sign-in is the default. After app consent changes, add
      -ForceAuthentication to obtain a fresh sign-in; no cache-file rename is needed.
      -AuthenticationMode DeviceLogin remains available where interactive sign-in
      is unsuitable; -ForceAuthentication applies only to Interactive.
  7. Read the final ADMIN HANDOFF: customer external sharing is OFF (Disabled).
     Keep the customer organization settings Disabled. Verify the site and Teams
     as described in runbook section 5.

CUSTOMER DEFAULT - EXTERNAL SHARING OFF; LAB PREVIEW IS OPT-IN
  CoESiteSharingCapability ships as "Disabled"; a missing setting also defaults
  to Disabled. Customer installations stay internal-only and do not need guest
  sharing enabled. Keep the Team Private and sharing owner-controlled.

  Only a separate, explicitly approved lab organization settings file should use
  "ExistingExternalUserSharingOnly" for authenticated existing-guest preview.
  The customer folder must stay Disabled. Never copy lab settings into a handoff.
  For lab preview, an owner grants Visitors Read access (site-wide read) or a
  "Specific people - Can view" link to selected reviewed files. Do not add preview
  guests to the Team or Members group: membership grants edit, not read-only access.
  Confirm the guest has no other edit grants. No anonymous/Anyone links are allowed.
  "ExternalUserSharingOnly" (New and existing guests) is an explicit lab option
  only if invitations are approved. The kit never invites guests.
  Leadership and Program Governance shared channels/sites remain internal-only;
  adding someone to the parent Team does not grant those governance permissions.
  The standard "Governance and Responsible AI" channel is on the parent site and
  is on the parent preview boundary if lab access is granted. Review ALL parent
  content before a site-wide Visitors grant; file links have a narrower scope.
  Site sharing ON is not proof that a guest can sign in. Tenant sharing, Teams/Groups
  guest settings, Entra B2B/cross-tenant policies, labels and conditional access can
  still block access. If preview is blocked, keep Disabled; do not loosen tenant
  policy to complete installation. Test each intended lab guest's read-only access.

  TURN OFF NOW (SharePoint administrator):
    SharePoint admin center > Active sites > select the CoE parent site > Settings
    > More sharing settings > Only people in your organization > Save.
  Or use an authenticated SharePoint-admin PnP session:
    Set-PnPTenantSite -Identity <exact-CoE-site-URL> -SharingCapability Disabled -Wait
    . .\Internal\SecurityPosture.ps1
    Set-CoENonOwnerSharingDisabled -SiteUrl <exact-CoE-site-URL> -Connection (Get-PnPConnection)
  Confirm SharingCapability is Disabled. Remove lab Visitors grants and Specific
  people links. If guests were previously added to the Team, also remove them
  under Team > Manage team > Members and guests to end Teams access.
  Disabling sharing does not delete grants; they may work again if sharing is restored.
  KEEP IT OFF: set "CoESiteSharingCapability": "Disabled" in the organization's
  Deployment-Settings.json BEFORE another 02 install/resume or 03 update.
  Reruns apply that setting; omission defaults to Disabled. An explicit lab ON
  setting can still undo a portal-only shutdown. Every successful install/update
  prints actual per-site ON/OFF status, the safe-default rationale and shutdown steps.

ADOPTION CATALOGS - LEARNING AND EXISTING INTERNAL AGENTS
  Training and Enablement now embeds 18 starter learning steps across six roles.
  Each step has Learn, Practice and What good looks like, with suggested practice time
  and explicit access prerequisites. The existing calendar, guides and Teams tabs remain.
  Use Content\Learning-Paths.json to tailor steps and Links.PromptLibrary/LearningSystem
  for customer-approved resources. The kit does not import EDU CSVs or track completion.
  Agent Showcase keeps the same list and launch links. Approved-agent and Featured views use
  one list; new metadata explains sources, allowed data, access/billing, owner/backup and review.
  The page purpose and review notice appear before the compact lists. Practice links open named prompts.
  Learning steps and Published are the default reader views on both new and existing lists.
  Open the list links open those views, not the bare All Items view. Learning roles use
  a defined order; details hide Learning ID and show Step, Learn and Practice first.
  Actual learning owners and review dates must be assigned/confirmed before launch.
  Native SharePoint content approval protects publication; existing list access is kept.
  CatalogReviewerUPNs receive Contribute plus ApproveItems, not Edit. Drafts remain visible
  to authors and approvers. Previously Published/Featured entries retain their visibility;
  new configuration links default to pending approval. Both views are always on the page,
  so approving or featuring entries does not require republishing it. Approval is the only
  publication gate; status Retired excludes an agent. Other legacy status values do not gate display.
  Apply with the usual 02 install or 03 -Scope Guides/All update after customer review.
  Existing page overrides stay in the organization folder. See Org-Template\README.txt
  for approval, permission review, prompt links and migration guidance.
  To retire an approved agent, set Retired and approve the change from Manage all entries.
  The previous approved version can remain visible until that retirement is approved.
  Revision 3.4 includes live list/permission fixes and verified Word-opening links for the
  Leadership and Program governance pages. Those links open Word in a separate browser tab,
  not a direct .docx download; the existing Word files and governance permissions are preserved.
  Install/resume explicitly verifies standard channel and resource-tab identities instead of
  trusting captured template IDs. Resume does not replay captured welcome posts.
  A content update preserves an intentionally removed Top 10 tab unless you explicitly run
  03_Update-CoEContent.ps1 -Scope All -EnsureResourceTabs to restore required resource tabs.
  Validate a fresh installation and your organization's overrides before production rollout.

HOME AND NAVIGATION
  Fresh Home has two introduction links (Start in 10 minutes; Which Copilot should I use?),
  tool cards and four area links. Demo mode also shows a live upcoming-sessions view (only
  approved future entries in Lists/CopilotTrainingCalendar appear; samples remain drafts).
  Customer mode never shows that live view - SharePoint's List web part reserves blank space
  up to its row count regardless of how many rows actually match, which reads as broken with
  zero or few real sessions - so Customer mode shows a "No sessions scheduled yet" heading
  next to the "See the full training calendar" link instead, until the organization adds
  real events.
  NavigationOrder TaskFirst builds the horizontal mega menu with a Standard site header
  so the section labels have their own row on the existing Teams site:
  Home, Get started, Copilot tools, Training, Agents, Governance, Community, Help.
  Headers do not navigate; each destination is one or two clicks away. Training contains
  Technical readiness, Microsoft Mechanics, Learning series and the Training calendar.
  Home and every managed section page link back to Home. AToZ and AsBuilt remain opt-ins.
  To deliberately rebuild a customized Home on an existing site after review:
    .\03_Update-CoEContent.ps1 -OrgPath <folder> -Scope All -RepairCapturedPages
  This replaces the Home controls and backs up the prior page; it does not capture
  tenant-specific site content into the kit. Ordinary updates preserve existing Home.
  Guided learning shows Microsoft Learn course cards: four common tracks, Educators and
  Students in higher education, and optional Developers. Set LearningEnvironment and
  EnableDeveloperTrack in the organization profile. Verify all course destinations and
  local policy before launch. Tools, agents and data pages show their actual review date.
  Data protection is under Governance; the incident menu item uses Links.DataSafetyIncident.
  No paid-license request call-to-action is created.
  A normal resume does not replace captured pages. Update the organization's
  NavigationOrder to TaskFirst if its older profile explicitly selected AToZ.
  Previously created orphan pages are preserved for administrator review; fresh builds
  omit the empty News-and-Updates page. No test agent is automatically approved or featured.

UPGRADING A SITE BUILT BY KIT 3.8 OR EARLIER
  A plain rerun of 03_Update-CoEContent.ps1 does NOT bring an already-built site's content pages up to
  date with every kit fix - most content page HTML (breadcrumbs, section labels, guide text, including the
  3.8.2 breadcrumb and "Learning paths" naming fixes) is written once by Write-ManagedPage and then
  preserved on every later run unless you pass -ReplaceManagedPages; an ordinary rerun intentionally leaves
  an already-existing page alone so it never overwrites a customer's own edits. Home's welcome-text block
  (Repair-CoEHubPages / Set-CoEHomeWelcomeText) follows the SAME rule, not an exception to it: it only runs
  when -RepairCapturedPages is passed (a fresh, non-resumed install always passes it; 03_Update-CoEContent.ps1
  only passes it through when you explicitly ask for it). A plain rerun never touches it, same as every
  other content page - it does not refresh itself automatically, and no earlier claim that it did was ever
  implemented that way.
  For a site built on an earlier kit version, to actually pick up content-page fixes (breadcrumbs, guide
  wording, section labels, Home's welcome text) do ONE of:
    .\03_Update-CoEContent.ps1 -OrgPath <folder> -Scope All -ReplaceManagedPages -RepairCapturedPages
        (rewrites every managed page from the current kit content, including Home; review the page's own
        prior version first - a backup of its previous field values is written to RevisionAudit before it
        is overwritten)
    or a fresh install into a new site, if you do not need to preserve the existing site's history.
  Test-CoEInstall.ps1 checks the CURRENT kit's expected content (current breadcrumb labels, "Learning
  paths" naming, and so on); a site that has not been through -ReplaceManagedPages/-RepairCapturedPages or a
  fresh install since the fix it is checking for will still show those specific checks as FAIL, and that is
  expected until one of the two upgrade paths above is used - it is not evidence the kit itself is broken.

IF THE BUILD STOPS PARTWAY
  Fix the cause named in the red message, then re-run with the same settings:
       .\02_Install-CopilotCoE.ps1 -OrgPath <folder> -SeedDemoContent -ResumeExisting
  Resume reuses the Team and site. It finishes the site template only when no
  CoE pages exist yet. With -SeedDemoContent, a resume keeps existing managed pages;
  use 03_Update-CoEContent only when you intend to republish managed content.

IF SHAREPOINT REPORTS AN HTTPCLIENT TIMEOUT
  If the error names Get-PnPFile and says "The request was canceled due to the
  configured HttpClient.Timeout of 100 seconds elapsing", the SharePoint request
  did not finish within the client timeout. The Team and site may already exist.
  Do not start a fresh install or purge the CoE. Confirm that the existing Team
  and site are the intended CoE, then run the same command again with
  -ResumeExisting:
       .\02_Install-CopilotCoE.ps1 -OrgPath <folder> -SeedDemoContent -ResumeExisting
  Resume reuses the existing Team and site and preserves existing managed pages.
  If the timeout repeats, stop and provide the full error output to your
  administrator or support contact.

UNDO - REMOVE THE COE (script 04)
       .\04_Remove-CopilotCoE.ps1 -OrgPath <folder> -WhatIf   (preview only)
       .\04_Remove-CopilotCoE.ps1 -OrgPath <folder>           (delete; restorable 30 days)
       .\04_Remove-CopilotCoE.ps1 -OrgPath <folder> -Purge    (permanent; frees the alias)
  Removes the Team, its SharePoint site, and only the related channel sites shown
  in the reviewed plan after you type the alias. A purge requires typing each exact
  reviewed site URL, one by one; the script executes only that frozen target list.
  The kit changes no tenant-wide sharing policy. The sign-in app is
  kept; delete it in Entra admin center if you no longer need it.

START OVER - PURGE AND REBUILD (runbook section 10.1)
  BACK UP FIRST: save the WHOLE organization folder, not just Deployment-Settings.json.
  It holds the settings (tenant, PnPClientID, owner, alias, agents, navigation), your
  Content\ overrides, and your Assets\ files. Use the copy that matches the tenant you
  are rebuilding (a copy with <placeholders> cannot drive a run). Also export anything
  added by hand in SharePoint or Teams; the purge deletes it.
  Survives the purge, no backup needed: the sign-in app and consent, Copilot agents,
  and user accounts. A local PnP sign-in cache is separate; clear it when no longer needed.
    1. Move-Item <kit>\Orgs\<org> C:\CoE-Orgs\<org>   (keep the org folder outside the kit)
    2. .\04_Remove-CopilotCoE.ps1 -OrgPath C:\CoE-Orgs\<org> -Purge
       (check AliasReusable : True; if not, run it again a few minutes later)
    3. Delete the kit folder, unblock the ZIP, and extract it again.
    4. .\02_Install-CopilotCoE.ps1 -OrgPath C:\CoE-Orgs\<org> -SeedDemoContent
       (skip 01: the app still exists; do not add -ResumeExisting)

CHANGE THE CONTENT LATER (script 03, as often as needed)
  For one organization: copy any kit text file from SeedContent into
  <folder>\Content at the same path, edit the copy, or add files to
  <folder>\Assets. Example: Content\Sections\04-Service-Catalog-and-Support.md
  to set approved service offerings. Runbook section 6 lists everything an
  organization can and should customize. Edit SeedContent only to change the
  default for every organization.
  Then run one of:
    .\03_Update-CoEContent.ps1 -OrgPath <folder> -Scope Guides     (pages, guides, sections, hosted files)
    .\03_Update-CoEContent.ps1 -OrgPath <folder> -Scope Governance -ReplaceFiles
    .\03_Update-CoEContent.ps1 -OrgPath <folder> -Scope All        (also the Top 10 deck)
    Add -ReplaceOrgAssets only after reviewing an existing asset; files are overwritten
    in place, not deleted before upload. Recovery depends on the library's version settings.
    Empty guide overrides remove managed navigation links but preserve existing pages.
    Empty policy overrides remove the proposed-policy link but preserve existing files.
    Review and retire previously published pages/files separately when necessary.
  Edit champion people and training dates directly in the SharePoint lists.

  01_Register-CoEProvisioningApp.ps1  Creates the sign-in app (approved consent approver, once per tenant)
  02_Install-CopilotCoE.ps1        Builds the CoE for the organization folder
  03_Update-CoEContent.ps1            Republishes edited content and new organization files

SAFETY
  Scripts 01-03 never delete groups or sites; content completion/update can recycle
  managed files, pages, and sample list items. Organization assets are never replaced
  unless you pass -ReplaceOrgAssets; managed governance files require -ReplaceManagedFiles.
  Only 04 removes the Team/sites after confirmation. The installer stops if the alias or
  site already exists; use -ResumeExisting only for your own partial build.
  Organization files are uploaded only after you answer Yes (or -AcceptOrgAssets);
  an existing file is preserved unless -ReplaceOrgAssets is supplied.
  A before-copy of replaced pages is kept in RevisionAudit.
  The installer requires a Private Team, disables parent-site external sharing
  by default, keeps governance sites internal-only, and prevents
  non-owners and members from sharing.
  Before publishing, it checks each governance channel's effective Graph allMembers
  roster (including indirect members), shared-Team relationships, and immutable
  in-tenant user and tenant IDs against the approved allowlist. Unknown, incomplete,
  cross-tenant, or unapproved governance access blocks publication. External-user
  entries on governance sites also block publishing; parent-site guests are reported
  for admin review, not rejected. A fresh security posture report is printed at the
  end of install and every content update. Existing anonymous/specific-people links,
  item-level grants, and the tenant cross-tenant access policy are not enumerated
  and still require separate review.
  The configured in-tenant owner is added to the Team if needed; membership notifications
  may be sent by Microsoft 365. The scripts do not invite external guests or invent people.
  Tenant-wide sharing policy is not changed.
  Do not run the original vendor InstallPackage-New.ps1 in SourceOriginal.
  SourceOriginal is a legacy folder name: the shipped PnP template is a hardened
  derivative (IsPublic=false, MembersCanShare=false), not byte-original vendor content.
  Never put tokens, passwords, or confidential records in the kit or org folders.
